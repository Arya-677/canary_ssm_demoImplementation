# Sandbox null audit (calibration only; NO power claims)

Generated by `scripts/summarize_audit.py` from the CSVs in this folder. Protocol: frozen declared hyperparameters
(`canary_ssm.experiments.FROZEN`, not tuned), nuisance fitted on 30 healthy dev rollouts, thresholds calibrated on
B=300 PLAIN nulls (k=286), noise SD 0.02, then B=200 fresh nulls per family with the policy frozen. Seeds: dev 1,000,000+,
calibration 2,000,000+, audit 6,000,000+ (no overlap with the handoffs' 400000-559999). One realisation, one machine;
95% intervals are about +/- 5 points at n=200, so differences under ~8-10 points are inconclusive. An 'upper bound <= 8%' gate is
unreachable at n=200 even for a correct 5% method, so this table only marks ABOVE (whole interval above 5%); the formal gate needs n >= 400 per cell.
`beta_mode=pre` = per-host slope from the rollout pre-period; `pooled_dev` = one development-pooled slope.
Families: `step` = sustained log(1.4) workload step with homogeneous slopes; `step_beta_heterogeneous` = same step with
slope jitter SD 0.08 across hosts (so host-specific slope error times the step is a persistent offset).

## What this does and does not show
* It reproduces, on this repo, the handoff's central failure: calibrated on plain nulls, adjusted CUSUM / top-K CUSUM alarm
  on most step-only nulls, the SSMs on a smaller but still unacceptable share, matched contrast least. The calibration gate
  is NOT met by any detector under a shared step with either adjustment mode.
* Pooling the slope helps when the workload response is homogeneous and hurts badly when it is not. No adjustment mode here
  is shown to be safe; the choice is confounded with how heterogeneous real hosts are (unknown).
* phi_e = 0.8 (true noise more persistent than fitted) inflates every model-based detector; matched contrast is unaffected.
  Heavy tails (Student-t, 3 df) inflate matched contrast most. Plain-null calibration is close to target for all methods.
* Frozen hyperparameters are the handoff's declared values, so this audits calibration mechanics only. It says nothing about
  which detector is faster or whether the hierarchy helps.
* Not tested here: nonlinear workload, loading shifts, missingness, white measurement noise (they are in configs/audit.yaml).
