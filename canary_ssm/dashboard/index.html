Welcome to the Canary SSM Experiment Runner

This interactive virtual datacenter demonstrates Hierarchical State-Space Modeling (HSSM) for canary deployment monitoring. It isolates release regressions from physical infrastructure confounders (such as rack network bottlenecks and fleet demand spikes) and compares partial pooling against independent and complete pooling in real time.

Statistical Explanation: Release Score & Posterior Risks Mathematical Reference

Release score: maximum host risk is defined as: \text{score} = \max_i \log P(a_i > \log(1.02) \mid \text{data} \le t).

• Boundary \(\kappa_{\text{lat}} = \log(1.02) \approx +0.0198\): Declared operationally meaningful effect threshold (+2.0% latency shift).
• Log Scale: Scores are in \((-\infty, 0.0]\). For example, \(-0.693 = \log(0.50)\) represents a 50% posterior probability of regression.
• Within-Class Shrinkage: Canaries shrink toward their hardware class mean via the Helmert contrast basis, damping random host noise while preserving sensitivity to genuine regression.

Side-by-Side Pooling Method Comparison on Current Replay Real-Time Shrinkage Analysis

Why does pooling matter? Independent SSM has high estimation variance because each host has little data. Complete Pooling assumes all canaries are identical, which washes out regressions isolated to a single host. Hierarchical SSM (Partial Pooling) uses Helmert contrast matrices to balance both extremes.
